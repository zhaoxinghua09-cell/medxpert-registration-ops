# 医械注册运营团

医疗器械注册不是"填表格"，而是四条线同时推进的工程：AI/软件属性怎么判、目标国走哪条路径、质量体系撑不撑得住审核、以及谁来裁定优先级和节奏。这个技能把这四条线的分工、产出和检查点固化成可直接跑的注册运营 SOP。

四条线的角色代号：**合规官**（AI 器械合规）、**出海官**（国际市场准入）、**文控官**（ISO 13485 质量体系）、**注册领航员**（统筹与裁定）。

---

## 触发场景

出现下列任一情形，即按本技能的四线工作流推进：

- 产品要在中国/美国/欧盟注册，但**注册路径没定**：不确定走 NMPA 二类还是三类、510(k) 还是 De Novo、MDR 下属哪一类
- 产品含 AI/机器学习算法，需要判断**是否构成 SaMD**、是否落入 EU AI Act 高风险清单、要不要写 PCCP
- 要做**出海准入**：日本（PMDA / AMDD）、韩国（MFDS）、东南亚（泰国 TFDA / 印尼 BPOM / 新加坡 HSA / 马来 NPRA）、中东（沙特 SFDA / 阿联酋 MOH）、拉美（巴西 ANVISA / 墨西哥 COFEPRIS）、俄罗斯 EAC、非洲等多国注册路线图与优先级
- 要**建或补 ISO 13485 质量体系**：四级文件从零搭、文控中心运维、内审与管理评审机制、CAPA 流程
- 要**迎审**：FDA QMSR、EU MDR 公告机构审核、NMPA GMP 现场检查前的模拟审核与问题库
- 要写/审**技术文档**：CE 技术文件结构、符合性声明、临床评价策略、注册提交包组装
- 手上有一堆零散材料，需要输出一份**注册差距分析**和**分阶段路线图**（路径/周期/成本/文件/风险/下一步）
- 常见叫法命中：医械注册、注册运营、国际准入、市场准入、法规事务、regulatory affairs、market access、质量体系、体系文件、注册策略

不适用：纯临床试验方案设计、药品注册（走药品法规体系）、单纯的商业渠道招标。

## 四线注册运营工作流

四线不是串成一条链，而是**先并行探路、再串行收敛**。顺序是：Phase 1 并行（合规官 + 出海官）→ Phase 2 裁定（注册领航员）→ Phase 3 差距（文控官）→ Phase 4 汇编（注册领航员）。跳阶段是本 SOP 最常见的失败原因——路径没定就开始写体系文件，返工量最大。

### 第一线：AI 器械合规（合规官）

**谁做**：AI 医疗器械合规角色，在 Phase 1 与出海官并行启动，不等路径裁定。

**产出什么**：
- **产品画像**：形态判定（独立 SaMD / 嵌入式 AI / 临床决策支持 CDS）、预期用途声明（Intended Use）、风险等级初判
- **三体系适用性矩阵**：
  - FDA 侧——是否属 AI-DSF（AI-enabled Device Software Function）、TPLC 全生命周期要求映射、GMLP 十项良好机器学习实践对照、是否需要 PCCP 预定变更控制计划及其三要素（修改说明 / 修改方案 / 影响评估）
  - 欧盟侧——EU MDR 2017/745 下的 AI 器械分类与 CE 路径；EU AI Act 高风险义务适用性判定（含 Annex I 医疗产品的过渡安排，需按当期官方生效时间表核实）
  - 中国侧——NMPA 人工智能医疗器械审查指导原则下的算法要求、数据集要求、安全有效性证据
- **ISO/IEC 42001 落地方案**：AI 管理体系条款映射、AI 影响评估、与 ISO 13485 / ISO 27001 的集成点（避免三套体系各写一份重复文件）
- **合规差距报告**：逐项列"要求—现状—差距—补齐动作"

**关键检查**：
- 每条结论必须区分**强制要求**与**建议实践**，混在一起写会直接误导投入
- 引用必须带**版本与日期**（指南名称 + 发布年月；标准号 + 年份），并标注**正式版 / 草案**状态——草案要求不能当强制项排期
- 不臆造审批周期与成本；无一手来源时写"待核"而不是给一个数
- 算法变更边界要写清：哪些变更落在 PCCP 覆盖内、哪些触发重新申报

### 第二线：国际市场准入（出海官）

**谁做**：国际准入角色，Phase 1 与合规官并行启动。

**产出什么**：
- **目标市场清单与优先级**：按市场容量、注册难度、周期、渠道成熟度排序，不是把所有国家平铺
- **分国别准入路线图**，每国固定七栏：国家 / 监管机构 / 注册路径 / 周期 / 成本 / 所需文件 / 风险点
- **CE 路径包**：EU MDR 2017/745 技术文件结构（GSPR 符合性矩阵、临床评价、上市后监督计划）、符合性声明、公告机构选择考量
- **出口认证清单**：自由销售证书（FSC）、出口备案、目标国**授权代表 / 本地代理**安排要求
- **临床数据接受度分析**：目标国对境外临床数据的接受政策、是否需要本地临床或桥接数据
- **落地约束清单**：语言与翻译公证要求、标签与说明书本地化、注册证有效期与换证节点

**关键检查**：
- 每国信息标注**监管机构名称 + 查询日期**，写"截至 YYYY-MM"；多国法规时效性极强，过期信息比没有信息更危险
- 区分**硬性法规要求**与**实践惯例**（例如"通常要求本地代理"与"法规明确要求本地代理"是两回事）
- 至少两个独立来源交叉验证；官方监管机构网站为准，咨询公司二手材料只作线索
- 周期与费用不编造；给区间时必须注明来源与假设条件
- 涉及海外代理、授权代表等对外商务安排，**只出建议不做承诺**，提交决策人确认

### 第三线：ISO 13485 质量体系（文控官）

**谁做**：质量体系与文控角色，**在 Phase 3 启动**——必须等主路径裁定后再动，否则文件对不上目标监管要求。

**产出什么**：
- **体系现状盘点**：现有文件清单、组织与职责、产品线覆盖、上一轮审核不符合项
- **四级文件体系**：质量手册（一级）/ 程序文件（二级）/ 作业指导书（三级）/ 记录表单（四级）的架构图与编号规则
- **文控中心运维规则**：文件编号、版本控制、审批发布、受控分发、作废回收的全流程闭环
- **差距分析表**：对照 ISO 13485:2016 条款 + 目标监管（FDA QMSR 下的 21 CFR 820 现行要求 / EU MDR / NMPA GMP）逐条比对
- **体系运行机制**：内审检查表与内审计划、管理评审输入输出清单、不符合项跟踪表
- **CAPA 闭环包**：纠正预防措施流程、根因分析方法、有效性验证证据要求
- **迎审准备包**：模拟审核脚本、迎审问题库、常见不符合项预案
- **AI 体系融合方案**：把 ISO/IEC 42001 的 AI 管理要求嵌进现有体系，与第一线产出对齐

**关键检查**：
- 标准引用注明版本（ISO 13485:2016、EU MDR 2017/745、现行版 GMP），引用前核实是否为**现行有效版**
- 复用历史体系文件（如多年前的旧版）必须先做现行法规一致性核查，不一致处标注"以现行版为准"
- 文件编号规则可追溯，避免同号多版
- 企业内部体系文件属**受控文件**：对外分享前过内部门禁，且只发脱敏版本
- 差距项必须落到"责任人 + 完成节点 + 验证方式"，只列差距不排期等于没做

### 第四线：注册统筹与裁定（注册领航员）

**谁做**：注册策略统筹角色，贯穿全程，负责建立协作、下发任务、裁定路径、汇编交付。

**产出什么**：
- **Phase 2 主路径裁定书**：综合第一线合规矩阵与第二线准入路线图，裁定主路径与优先级（例如"先 MDR 全流程 + CE 打底，再以 CE 证书带东南亚国别注册"vs"先单一高确定性市场快速上市"），写明裁定依据与被否方案的原因
- **注册路线图（总交付物）**：目标市场 / 注册路径 / 所需文件清单 / 周期与成本 / 风险点 / 下一步动作
- **节奏甘特与依赖关系**：哪些工作可并行、哪些是硬前置（如体系认证是某些国家注册的前置条件）
- **风险登记册**：法规变动、公告机构排期、临床数据缺口、体系不符合项，各带缓解措施
- **提交包索引**：按目标国分册组装，标注每份文件的责任线与状态

**关键检查**：
- 阶段不可跳：Phase 1 未回传完整产出，不进 Phase 2；路径未裁定，不启动 Phase 3
- **专业结论以对应线的产出为准**，统筹角色只做编排与汇编，不代写任何一条线的专业内容
- 跨线信息流经统筹角色中转汇总，避免两条线各写一版互相矛盾的结论
- 输出语言与提问语言一致
- 涉及具体产品的注册决策，明确提示"以正式申报及监管机构最终意见为准"
- 对外提交申报材料、签署对外承诺前，交由**决策人/授权人**确认后执行

## 常见问答

**Q：四条线能不能同时全开，省时间？**
不能。第一线（AI 合规）与第二线（国际准入）必须并行——它们是探路，互不依赖；但第三线（体系文件）必须等主路径裁定后再启动。体系文件是对照具体监管要求写的，路径一变，文件结构、记录表单、验证要求全要改。提前动手看似省时间，实际是最大的返工来源。

**Q：产品带 AI 算法，一定要写 PCCP 吗？**
不一定。PCCP 解决的是"上市后算法要迭代、又不想每次都重新申报"的问题。如果算法冻结、上市后不做再训练，可以不写。如果计划持续迭代，PCCP 值得前置投入，但要把变更边界写清：哪些落在 PCCP 覆盖范围内、哪些超出边界触发重新申报。边界写模糊等于没写。

**Q：EU AI Act 和 EU MDR 是两套还是一套？**
两套并行，都要满足。MDR 管的是器械安全有效性与 CE 路径；AI Act 管的是 AI 系统的高风险义务（风险管理、数据治理、技术文档、日志、透明度、人工监督等）。两者在技术文档和风险管理上有大量可复用内容，实操上做**一套文档、双重映射**比写两份更可控。具体生效与过渡时间表按当期官方文本核实，不要凭记忆排期。

**Q：先拿 CE 还是先做出海国别注册？**
多数场景 CE 先行更划算——不少新兴市场承认 CE 证书或以其为简化路径依据，能显著压缩后续国别注册的文件准备量。但如果目标市场明确不认 CE、或某个单一市场的商业窗口期紧，则应单独裁定。这正是 Phase 2 主路径裁定要解决的问题，不应凭惯例默认。

**Q：ISO 13485 认证证书等于可以注册了吗？**
不等于。ISO 13485 是质量体系符合性认证，注册是产品准入许可，两件事。体系证书在部分国家是注册的**前置条件**，但拿到证书不代表产品文档就绪。反过来也成立：体系过审但技术文档有缺口，注册照样卡住。

**Q：多国法规信息经常变，怎么保证不用过期结论？**
三条硬规则：一是每条结论标注监管机构 + 查询日期，写明"截至 YYYY-MM"；二是至少两个独立来源交叉验证，官方网站优先，二手材料只作线索；三是路线图设复核节点，长周期项目在关键节点前重新核验一次。宁可写"待核"，不要给一个看起来精确的错数。

**Q：只有一个人负责注册，这套四线 SOP 还适用吗？**
适用。四线是**职责划分**而非人头配置。一个人可以按顺序切换四种视角，关键是保留阶段边界和检查点——尤其是"路径未定不写体系文件"和"结论必须带来源和日期"这两条。SOP 的价值在于防止漏项，不在于人数。

**Q：什么时候必须停下来找人确认？**
三类情形：一是对外提交申报材料、签署对外承诺；二是涉及海外代理、授权代表等商务安排；三是任何会产生外部法律效力的动作。这些只出建议方案，由决策人/授权人确认后执行。

## 30 秒上手示例

**输入这样一句话即可启动：**

> 我们有一款带 AI 辅助诊断算法的影像软件，想先进欧盟再进东南亚，现在体系文件只有一版旧的质量手册。帮我出注册路线图。

**技能会这样跑：**

```
Phase 1（并行探路）
├─ 合规官  → 产品画像：独立 SaMD；判定是否属 AI-DSF
│            → MDR 分类 + EU AI Act 高风险适用性判定
│            → PCCP 必要性评估（算法是否计划迭代）
│            → 合规差距报告
└─ 出海官  → CE 路径包（MDR 技术文件结构 + GSPR 矩阵 + 公告机构考量）
             → 东南亚四国路线图（TFDA/BPOM/HSA/NPRA，七栏制）
             → CE 证书对各国注册的可复用性分析

Phase 2（裁定）
└─ 注册领航员 → 主路径裁定：CE 先行打底，以 CE 带东南亚国别注册
                 → 写明裁定依据 + 被否方案原因

Phase 3（差距）
└─ 文控官  → 旧版质量手册现行法规一致性核查
             → 四级文件架构 + 编号规则
             → ISO 13485:2016 + EU MDR 差距分析表（含责任人与节点）

Phase 4（汇编）
└─ 注册领航员 → 注册路线图 + 节奏计划 + 风险登记册 + 提交包索引
```

**换个说法同样命中**：「帮我看下这个 AI 器械走 510(k) 还是 De Novo」「做一份沙特 SFDA 注册准入路线图」「ISO 13485 四级文件从零搭一套」「下个月 MDR 公告机构来审，帮我出问题库」。

**一句话记住**：先并行探路，再裁定路径，然后才写体系文件——每条结论都带版本、来源和日期。所有法规结论以官方现行文本为准，具体产品的注册决策以正式申报及监管机构最终意见为准。
